# Phase 5 settings and optional provider foundation

`sendSecurityNotification(to, event)` supports only `PASSWORD_RESET_COMPLETED` and `SESSION_REVOKED`. It uses fixed categorical text, the same configuration/recipient/timeout gates, and a fresh UUID idempotency key for each notification. No token, session identifier, user code or IP is included. Notification failure does not undo the security action. Security notification transport is covered by isolated tests; actual approved inbox verification remains open.

M2 R12 / A41–42 / B15 / B18: core compiler operation requires no provider credentials. Both adapters default disabled. No live provider write has been performed or verified. Isolated transport fixtures exercise request construction, acceptance/error handling and privacy filtering; they are not delivery evidence.

`ProductIntegrations(config.integrations)` uses native HTTPS fetch with a bounded 10–5000 ms timeout including response parsing, rejects redirects, and never logs provider requests, tokens, passwords or responses. Resend requires `RESEND_ENABLED=true`, API key, a bare `RESEND_FROM` mailbox and an explicitly configured HTTPS `PUBLIC_BASE_URL` origin. `sendPasswordReset(to, token)` builds `/reset-password?token=...`, uses text-only content and a token-digest idempotency key. It returns only `disabled`, `unconfigured`, `rejected`, `accepted`, or `failed`. Provider acceptance is not inbox delivery. Existing expiring single-use reset tokens remain authoritative; production API responses must never contain reset tokens. Security/optional notification delivery and actual approved inbox verification remain open.

`capture(event, analyticsOptIn, properties)` requires server configuration and per-owner opt-in. Hosted PostHog ingestion origins are restricted to US/EU. Every event gets a new random UUID, disables GeoIP and person profiles, and exports only enumerated language/status/platform/taskKind categories. Unknown events are rejected; arbitrary property values/keys are discarded. No source, user email, stable owner id, URL, IP, cookies, credentials, job payload or local path is exported. This deliberately permits aggregate counts, not cross-event user funnels. No browser SDK, autocapture or session replay is enabled. Provider quota limits count as failure; failure must never fail a core workflow.

Allowlisted events: application_opened, signup_completed, login_completed, compiler_submission, job_completed, job_failed, worker_enrolled, worker_connected, worker_disconnected, network_created, task_completed, task_reassigned. Server hooks must obtain authoritative owner consent; missing owner/consent means no capture. This module provides transport foundation; hooked routes must be verified separately.

`UserSettingsStore(pool)` persists analyticsOptIn, notificationOptIn and reducedMotion (all default false) in `users.preferences_json`; migration 0009 must append the JSON column without modifying adopted migrations. Partial writes use atomic JSON_SET so independent concurrent field updates cannot overwrite one another. Unknown/nested/non-boolean fields are rejected. Existing auth_sessions are reused, active sessions are capped at 100, public ids derive from the stored hash, and no token/IP/user-agent hash is returned. Revocation is owner-scoped and existing auth immediately rejects revoked sessions.

`registerSettingsRoutes(app, {store, authenticate(request), currentSessionToken(request), audit?})` reuses existing auth, without new cookies/password/session logic. GET/PATCH `/api/user/settings` returns the preferences object; GET `/api/user/settings/sessions` returns `{items:[{id,createdAt,expiresAt,current}]}`; DELETE `/api/user/settings/sessions/:sessionId` returns `{revoked:true}` or owner-safe 404. The integrator must preserve existing origin guards and cookie policy. Audit callbacks receive only user id and fixed event name.

Validation: `npx vitest run apps/coordinator/src/product-integrations.test.ts apps/coordinator/src/user-settings.test.ts --maxWorkers=1`. Initial module-absence runs failed before implementation. A real behavioral regression with provider headers but a stalled body then failed by timeout; moving body parsing into the bounded request fixed it. MySQL persistence/session revocation requires the separately isolated coordinator fixture, not these transport/route tests.
