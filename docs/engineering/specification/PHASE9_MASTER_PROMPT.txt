# 4. COMPILER AND DISTRIBUTED-EXECUTION VALIDATION

Test the existing GRID-X compiler and optimization functionality rather than replacing it with UI demonstrations.

Cover C, Python, and Java according to their actual supported pipelines.

For each language, verify the applicable stages:

- Input validation.
- Lexical, syntactic, semantic, or source analysis where implemented.
- Intermediate representation generation where supported.
- Real optimization passes and preservation of program semantics.
- Toolchain detection.
- Actual compilation or execution where supported.
- Generated artefact correctness.
- Error reporting and build-report generation.
- Task scheduling and result verification across compatible workers.

Use small valid programs, more complex programs, malformed programs, and edge cases.

Where possible, compare program outputs before and after optimization. Use deterministic tests and appropriate timeouts.

Test optimizations such as constant folding, constant propagation, dead-code elimination, and algebraic simplification only where the implementation genuinely supports them. Do not claim that an optimization occurred merely because a report lists its name.

Distinguish source analysis, IR optimization, compilation, bytecode generation, and execution. They are different capabilities.

Never produce a fake `.exe`, `.class`, `.jar`, or other artefact to satisfy a test. Windows executable generation requires a compatible target toolchain. Android may support a different subset of tasks from Windows.

Verify that the scheduler assigns work based on registered capabilities and that unsupported jobs are rejected or routed elsewhere rather than failing silently.
